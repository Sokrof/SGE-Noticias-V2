INTRODUCCIÓN
El componente Segments (<ion-segment>) proporciona un control de nivel superior
para alternar entre diferentes vistas o categorías dentro de un mismo contenido. Es
similar a las pestañas (Tabs), pero se utiliza comúnmente para la navegación interna y la
filtración de contenido dentro de una página.



El componente actúa como un contenedor para múltiples botones de segmento
(<ion-segment-button>). Cada botón de segmento representa una vista o categoría que
el usuario puede seleccionar.



La      documentación        oficial    de      Segments       se     encuentra      en:
https://ionicframework.com/docs/api/segment

Explicación (HTML)

<ion-segment>: Contenedor principal de los botones de segmento.

[value]="segmentValue": Define qué botón está seleccionado actualmente. Se
enlaza a una propiedad TypeScript.

(ionChange)="segmentChanged($event)": Evento que se dispara cuando el
usuario selecciona un botón diferente. Permite capturar la nueva selección.

<ion-segment-button          value="friends"> : Define cada botón dentro del
segmento.

value="friends": Define el valor único del botón, que será el valor de salida en el
evento ionChange y el valor usado para el binding en [value].




EJEMPLO (LÓGICA TYPESCRIPT)

En el componente TypeScript, definimos el valor inicial del segmento y la función para
manejar el cambio de selección.

// Inicializamos la variable con el valor por defecto

public segmentValue: string = 'friends';



// Función que se dispara al cambiar el segmento

segmentChanged(event: any) {

 // El evento contiene el nuevo valor seleccionado

 this.segmentValue = event.detail.value;

 console.log('Segmento seleccionado:', this.segmentValue);

}




                                         ​ ​          ​         ​    ​        6
Explicación (TypeScript)

   1.​ public segmentValue: string = 'friends';: Esta variable
      almacena la vista actual. Inicialmente, se establece en 'friends' para que el
      primer botón aparezca seleccionado por defecto.
   2.​ segmentChanged(event: any): Esta función se ejecuta cada vez que el
      usuario pulsa un botón.
   3.​ event.detail.value: Contiene el valor (value) del botón que el usuario
      acaba de seleccionar (ej: 'albums'). Este valor se usa para actualizar
      segmentValue, lo que a su vez activa la renderización condicional del contenido
      en el HTML (@if).

SEGMENTOS Y QUERY PARAMETERS
En este enfoque, el componente SegmentsPage hará tres cosas:

   1.​ Leer el parámetro de consulta (segment) de la URL al inicializarse.
   2.​ Actualizar el valor del ion-segment con ese parámetro.
   3.​ Cambiar el parámetro de consulta en la URL (sin navegar fuera) cada vez que se
       presiona un botón del segmento.




Ejemplo estructurado con los siguientes archivos:

   1.​ main.ts: Habilitar el binding de inputs.
   2.​ segments.page.ts: Componente padre que maneja el Segment y actualiza
       la URL.
   3.​ segment-content.component.ts: Componente hijo que recibe el valor
       vía @Input y usa ngOnChanges.

COMPONENTE PADRE: SEGMENTS.PAGE.TS

El cambio clave aquí es que el constructor y el ngOnInit se simplifican enormemente, ya
que el router inyecta el valor de la URL en la propiedad @Input() antes de que se llame a
ngOnInit. Usaremos ngOnChanges para reaccionar a la primera carga y a los cambios de
la URL.

// Implementamos OnChanges para reaccionar al cambio en el @Input



 // El @Input recibe directamente el valor del query parameter 'category'.

 @Input() category!: string;



 public categories: CategoryView[] = [

      { value: 'monsters', label: 'Monstruos' },

      { value: 'materials', label: 'Materiales' },

      { value: 'equipment', label: 'Equipamiento' },

      { value: 'creatures', label: 'Criaturas' },

      { value: 'treasure', label: 'Tesoro' }

 ];



 // currentCategory ahora solo se usa para enlazar el [value] del ion-segment

 public currentCategory: string = this.categories[0].value;

 private validCategories = this.categories.map(v => v.value);

 private readonly router: Router = inject(Router);




 // ngOnChanges reacciona cuando el router actualiza el @Input(category)

 ngOnChanges(changes: SimpleChanges): void {

      if (changes['category'] && changes['category'].currentValue) {

       const newCategory = changes['category'].currentValue;




                                        ​ ​         ​      ​       ​        10
         // Sincronización del segmento: El valor del router actualiza la variable de UI

         if (this.validCategories.includes(newCategory)) {

             this.currentCategory = newCategory;

         }



         // Si el valor es inválido o se carga sin él, forzamos el valor por defecto

         if (!newCategory || !this.validCategories.includes(newCategory)) {

             this.updateQueryParam(this.categories[0].value);

         }

     }

 }



//Se dispara al cambiar el segmento: actualiza la URL y fuerza el cambio de @Input.

 segmentChanged(event: any) {

     const newCategory = event.detail.value;



     if (newCategory) {

         // Escribir el nuevo valor en la URL

         this.updateQueryParam(newCategory);

     // El cambio de URL reejecutará ngOnChanges en este componente y el
componente hijo

     }

 }



 private updateQueryParam(category: string) {

     this.router.navigate([], {

         queryParams: { category: category },

         queryParamsHandling: 'merge'

     });

 }

}

Resumen del Flujo de Datos

    1.​ El usuario hace clic en el segmento (ej: Materiales).

    2.​ El método segmentChanged() en SegmentsPage se ejecuta y llama a
        updateQueryParam('materials').

    3.​ updateQueryParam         usa    el    Router    para        cambiar   la   URL   a
        .../ruta?category=materials.

    4.​ El router (gracias a withComponentInputBinding) detecta el cambio en el query
        parameter category y actualiza el @Input('category') del componente hijo
        (SegmentContentComponent).

    5.​ El lifecycle hook ngOnChanges en SegmentContentComponent se activa.

    6.​ ngOnChanges llama a fetchCategoryData('materials'), que realiza la llamada
        HTTP a la API.

    7.​ El hijo muestra la lista de elementos actualizada.
